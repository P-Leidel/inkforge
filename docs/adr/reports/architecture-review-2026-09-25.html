Problem

A body kind has no module of its own: Rubble took 18 hunks of the Sandbox world in #16, and #17–#19 thread Bond, Droplet, Patch and Blast through the same eight places.

Solution

Each kind owns its records, ids, views, snapshot part, rebuild, clear, cap and "host gone" handling; the Sandbox world runs those across all kinds once, in a fixed order.

Wins
  • locality: all of Rubble in one module
  • leverage: Reset and Clear written once
  • replay test covers every kind
  • "host gone" reaches every dependant
  • an enemy is one new module
  • Sandbox world tests stay the seam

Problem

Whether a contact counts (which Party, settled, sliding, one impact per Stroke) is decided inside the damage loop, and the handoff README tells each later slice to "skip settled pairs the same way" by hand.

Solution

One module behind the StepReport owns Parties, settled pairs and the touching set, and hands every rule hits, new contacts and touching Parties that already passed those filters.

Wins
  • locality: settled rule lives once
  • a new rule is a consumer
  • one test: settled never counts
  • numeric Party ids, not strings
  • enemy rules plug in

Problem

Release, waking and the end of a slide destroy and recreate the Box2D body, so every attachment is carried over by hand; the #18 handoff lists five functions to change for Patch shapes, and #17 adds re-creating bonds.

Solution

The adapter keeps one complete description of each body (shapes and their roles, surface, mass, damping, filters, bonds), and every rebuild, surface change or mass change is applied from it.

Wins
  • locality: rebuild rules in one record
  • attachments become data
  • one rebuild test, every attachment
  • clearer target for a Rapier adapter

After: one update per step, from what moved 
sequenceDiagram
  participant P as Box2D adapter
  participant W as Sandbox world
  participant R as Renderer + F1
  P->>W: step: bodies that moved
  W->>W: update read model
  R->>W: read model, once per frame
Problem

Work per step and per frame grows with every body, not with what changed: views are rebuilt on each read with several adapter calls per body, and each step copies every moving body's velocity whenever any Frozen Object exists.

Solution

The Sandbox world keeps one read model, updated once per step from the bodies that actually moved, and the renderer, F1 overlay and scene read that.

Wins
  • cost follows what moved
  • one read per frame
  • renderer checks read plain data
  • #21 verdict shows the gain
Measure first: #21's Demolition timings say whether this is needed before enemies arrive.

Problem

Every Line, Object and pebble is its own Graphics built from hundreds of tiny draw commands, and each Colour's look is spread over two switch statements and two black-crack checks.

Solution

An ink look module draws each look once into a cached texture, Rubble, Droplets and Patches become sprites sharing those textures, and each Colour's look is one entry.

Wins
  • draw cost flat per thing
  • sixth Colour look: one entry
  • sprites batch; Graphics don't
Check first: confirm Phaser 4 redraws a Graphics from its command list each frame, and read the #22 frame times.
Top recommendation

Give each body kind its own module

#17–#19 add four body kinds and milestone 4 adds enemies. Moving just Strokes and Rubble now turns each later slice from 18 hunks in one file into one new module, and the headless Sandbox world tests already sit at the interface that must not change. The Contact ledger is the natural second step, before #17 builds sticking on the old loop.

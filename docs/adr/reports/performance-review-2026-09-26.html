Inkforge performance review

P-Leidel/inkforge · 703e786 (#21 Demolition) · 2026-09-26

Scope: why the Demolition scene misses #22's frame-rate check, why F1 makes it worse, and what to change, from code to art. Each recommendation is rated on priority (P0 do now … P3 only if measurements ask for it) and blast radius (S: one rendering file, no change to the simulation · M: several files or a new Sandbox world command with tests · L: crosses modules or changes the look).

The finding

Physics is cheap. Drawing the ink is the frame.

Phaser 4 replays every Graphics object's full command list on every frame, whether or not it changed. Each fillCircle becomes a 100-step arc (100 sin/cos pairs and 100 new point objects), then an Earcut triangulation, then a vertex upload. The placeholder ink looks are built from thousands of tiny circles: grain, drips and round joints. After the Demolition chain, the screen holds 52,735 Graphics commands, re-tessellated 60 times a second. 80% of them are the 62 pieces of Rubble. The whole Sandbox world step costs about 0.34 ms (ADR 0001).

In a test with the Strokes, Rubble and Patches hidden (the upper bound for baking them into textures), the median frame fell from 21 ms to 1.8 ms. The HUD also re-renders a text texture every frame, and the F1 overlay adds one Phaser Text per durability label, which roughly doubles render time.

What was measured

Headless Chromium with SwiftShader (software WebGL) at 1920 × 1080, 5 s from the start of each run, one run each. Software GL makes every absolute number several times worse than a laptop GPU. Why F1 costs so much
  • One Phaser Text per durability label: 60 in the Demolition scene, 252 with the 24 extra Lines. Each is its own canvas texture, so each breaks the draw batch, and each label that changes is re-rendered and re-uploaded.
  • The stats text changes every frame (fps), so it is re-rendered and re-uploaded every frame.
  • Collider outlines are drawn with arcs (capsule ends, Rubble circles), so they are re-tessellated like the ink.
  • It reads world.lines twice and world.objects once per frame, and each read builds fresh view objects.
  • The extra fps and longest-frame figures only appear in the Demolition scene. Anywhere else there is no longest frame to read.

Suggested order, as issues

  1. R1 + R6, one small PR. It removes a texture upload from every frame. No change to the look or the simulation. Done, with A2's thinner grey grain (see below).
  2. M1, the new F1 overlay. Everything after this is measured with it, and it is the tool #22 reads.
  3. R2, Rubble as shared textures. It removes the largest single cost (80% of commands after the chain). It also proves the baking approach on the simplest case: Rubble never changes its look.
  4. T1, the Eraser. It makes testing fast: clear a wall, re-run a chain.
  5. R3, bake Strokes, Patches and the static UI (candidate 7 of the review after #19, now justified by these measurements). A1 is only needed if R3 slips.
  6. M2, a render budget test in Vitest, so an ink look can't quietly bring the cost back.
  7. Re-run #22 on the laptop with the new F1 readings. Then R4/R5 if the longest frame is still over 33 ms. Keep A3 for when the placeholder art is replaced.

Expected result after steps 1, 3 and 5: the per-frame Graphics replay drops from about 53k commands to the few thousand that really move (Debris, Droplets, Blast rings, bonds). That matches the green rows above.

R1

HUD: set the status text and colour only when they change

P0Blast radius S

Hud.draw calls setColor every frame. Unlike setText, that always re-renders the Text's canvas and re-uploads its texture: 10% of main-thread time in the profile. Remember the last running state and return early.

Done. The HUD touches the status Text only when the world starts or pauses.

src/rendering/hud.ts

R2

Rubble as Images sharing one baked texture per Colour

P0Blast radius S

Rubble never changes its look, and every piece of a Colour looks alike. Draw each Colour's disc once, at the largest Rubble radius, into a texture. Show each piece as an Image scaled to its radius, positioned, rotated and faded as now. Images sharing a texture batch into one draw call, and nothing is re-tessellated.

Gain
About 42k of 53k commands per frame after the chain.
Look
The grain scales a little with each piece's size, which is hardly visible at pebble sizes.
Choice
Bake through a WebGL DynamicTexture so the look is pixel-identical. Graphics.generateTexture draws with Canvas 2D, which antialiases differently.

src/rendering/world-renderer.ts (syncRubble, drawRubble) · a small texture cache module in src/rendering/

R3

Bake each Stroke, Patch and the static UI into a texture when its look changes

P1Blast radius M

The renderer already knows when a look changes (drawnLook, drawnLineLook). At that moment, draw the Graphics into a texture sized to its bounds and show an Image. Objects keep moving by their transform, as now. Do the same for the Terrain, the palette swatches and each Patch.

Gain
Lines, Objects and Patches stop being replayed every frame. A grey 80 px box alone is 7,000 commands.
Costs
A re-bake when cracks appear (one-off, during the chain). Texture memory of about 4 bytes per pixel of bounds (a 400 × 40 Line is 64 KB). Textures must be freed on remove, Clear and R.
Watch
Bounds must include the drips below green ink and the Outline width. Object textures rotate about the body's origin, not the texture's centre.

src/rendering/world-renderer.ts · src/rendering/palette-bar.ts · the texture cache from R2

R4

Debris and Droplets without tessellation

P2Blast radius S

Each Debris square is a 4-point fillPolygon, which runs Earcut every frame (3,960 commands in the chain). Use two fillTriangle calls, or pooled Images of one tinted white square. Droplets become pooled Images of a baked disc-with-glint per Colour. The simulation stays in Debris and Droplets; only the renderer changes.

src/rendering/world-renderer.ts (drawDebris, drawDroplets)

R5

A cheaper stroke preview

P2Blast radius S

While a Stroke is being drawn, StrokePreview redraws the whole path with its full texture every frame. A long grey Stroke gets slower to draw the longer it gets. Draw the preview as a plain band in the Colour's hue plus the texture only for the last 100 px, or bake the finished part every 30 samples.

Art and animation
A1

Specks as quads, not circles

P1 only if R3 slipsBlast radius S

A grain speck of radius 0.9 px is drawn as a 100-step arc, then triangulated. At 1080p a 2 × 2 fillRect looks the same and is one quad. Apply it to grey grain in Lines and Fills and to the smallest green dots. It's a stopgap: once R3 lands, specks are baked anyway.

src/rendering/ink.ts

A2

A pattern budget per Colour

P2Blast radius S

Grey costs 10 to 30 times what black does for the same ink, only because of grain density (a speck every 2.5 px along a Line, every 4 px across a Fill). Give each Colour's look a budget in draw calls per 100 px, and thin grey's grain to match green's and red's. That keeps unbaked paths (the preview, Debris) cheap, and it keeps the look readable for the blind check, where each Colour must be told apart by texture.

Done. Grey's grain only, as decided: a speck every 7 px along a Line (was 2.5) and every 8 px across a Fill (was 4), each a little larger so the grain still reads, and one colour change per shade instead of per speck. A 400 px grey Line now draws 57 grain circles instead of 160; an 80 px grey box, 100 instead of 400. The budget per Colour is still open.

src/rendering/ink.ts

A3

Real ink art as textures: Rope for Lines, textured Mesh for Fills

P2, with the real artBlast radius L

When the placeholder looks are replaced, author each Colour as a tileable strip texture (a Line or Outline) and a tileable fill texture. Phaser 4 has Rope, a textured strip along a list of points, and Mesh2D. A Line becomes one Rope and a Fill one textured mesh over the triangulated Outline. Each is a single draw from a shared texture, and cheap to rebuild when the shape changes. This is what makes hand-made brush art cost less than today's procedural shapes, instead of more.

A4

A render scale option

P3Blast radius S

The canvas is always 1920 × 1080 with MSAA, then scaled to fit. If a laptop turns out to be fill-rate bound once the CPU cost is gone (M1's render ms will show it), offer a 0.75 render scale or turn off antialiasGL on that setting. Nothing measured so far asks for this.

S1

A revision number on the material table

P3Blast radius S

applyMaterials runs JSON.stringify on the whole table every physics step to spot F2 edits. A revision counter that the tuning panel bumps does the same for free. It's small against a 0.34 ms step, so do it when you're next in that code.

src/sandbox/sandbox-world.ts · src/rendering/tuning-panel.ts

S2

One read of the world per frame

P3Blast radius M

The view getters build new objects on every read, and the renderer, the overlay and the HUD each read on their own. #21 measured every read at 0.06 ms a step, so this only matters for garbage collection (3% here). It is candidate 4 of the review after #19; keep it for when enemies add readers.

S3

Know that the world slows down, not the frame rate

P3, a noteBlast radius S

The world advances by Phaser's smoothed delta. Phaser clamps it to 16.7 ms for 120 frames after a page load or a return to the tab, and replaces any delta over 200 ms. On a slow machine the chain plays in slow motion. Physics then costs less per frame than it would at full speed, and a replay looks calm while it isn't. The frame tracker already reads rawDelta, which is right. For #22, start the chain a few seconds after the page loads. There is nothing to change unless it shows up in play.

Testing tool
T1

The Eraser

P1Blast radius M

A sandbox tool that removes what it passes over, quietly. It is for testing, not a game mechanic: in the game, the Build Phase has undo and the Wave has nothing.

Pick itE or a sixth swatch after the five Colours. Keys 1–5 go back to drawing. The cursor shows the brush as a circle (radius 12 px). Use itClick or drag. Everything the brush touches goes: a whole Object with its Fill, the Pieces of a Line it crosses (so you can cut a gap in a wall), Rubble, Droplets and Patches. QuietlyErasing is not breaking. There is no Debris, no Fill released, no Blast, and nothing is damaged. A green Object bonded to what was erased falls free, as when its host breaks (the ledger's "gone"). WhenPaused and running. What was erased while running comes back with R, like everything since the start. Erasing while paused is part of the next start's snapshot. UndoErasing isn't undone, and it removes the erased Strokes from the undo history (as remove does now).

Build it as one Sandbox world command, eraseAlong(path, radius), so it is tested headless like every other command. Tests: an erased red Object makes no Blast; an erased host lets its green Object fall; erasing one Piece keeps the rest of the Line fixed; R after erasing while running brings everything back.

src/sandbox/sandbox-world.ts · strokes.ts (Pieces under a brush, quiet Piece removal) · rubble.ts / droplets.ts / patches.ts (remove by id) · src/scenes/sandbox-scene.ts (tool mode) · palette-bar.ts · hud.ts (help text) · CONTEXT.md (Eraser, sandbox only)

Decisions

  • Eraser on Lines: it removes only the Pieces it touches. No Shift for the whole Line.
  • Baked look: a WebGL DynamicTexture, pixel-identical to today.
  • Grey grain (A2): thinned now, not left for the real art.
